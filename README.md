# Idea Farm Client Hub (trial build)

Clients send requests and approve work here instead of by email. The team answers, updates status and sends approvals. Planned home: **hub.theideafarm.com** on Webflow Cloud.

**Status: step 4a done.** monday is connected: requests, replies and status changes sync to the "Hub Requests" board. GHL client emails still wait in the team's **Outbox** page (step 4b).

## Run it

```bash
npm install
npm run db:reset   # creates the local database and loads sample data
npm run dev        # http://localhost:4183
```

To test the real Webflow Cloud build locally (Cloudflare Workers runtime):

```bash
npx opennextjs-cloudflare build
npm run preview:worker   # http://localhost:4184
```

Test logins are generated by `npm run db:seed` and saved to `seed/dev-logins.txt` (local only, not real accounts).

## How it's built

- **Next.js 15** on Cloudflare's runtime via `@opennextjs/cloudflare`, which is what Webflow Cloud runs.
- **SQLite (D1)** database through Drizzle. Schema: `src/db/schema.ts`. Migrations: `migrations/`.
- **File storage (R2)** for photos and PDFs clients attach. Files are only served to the client company that owns them, and to the team.
- **Logins:** one shared login per client company. The person types their name on each request, and it's remembered on that device.

## Security

- **Nobody chooses or sends passwords for someone else.** Admins make a one-time link (welcome: 72 h, reset: 24 h); the person sets their own password (12+ characters). Making a new link cancels the old one.
- **First admin on the live Hub (Webflow Cloud):** add a secret variable `SETUP_SECRET` (24+ random characters) in the environment settings and redeploy, open `/setup`, enter the secret, your name and email, then choose your password. `/setup` only exists while that secret is set and no admin has a password; afterwards it's gone. Delete `SETUP_SECRET` once you're in.
- **First admin locally:** `npm run admin:invite -- --name "Full Name" --email you@theideafarm.com` (prints a one-time link in the terminal).
- **Passwords** are hashed (PBKDF2-SHA256, 100k rounds). **Sessions and links** are stored only as SHA-256 fingerprints, so a copy of the database can't be used to sign in. Session cookie: httpOnly, SameSite=Lax, Secure in production.
- **Lockouts:** 5 wrong passwords for an email (or 25 from one network) in 15 minutes locks sign-in for 15 minutes. A wrong email and a wrong password get the same message.
- **Deactivate** a client or team member in Admin: they're signed out everywhere at once and their links stop working. An admin can't deactivate or demote themselves, and the last admin can't be removed.
- **Access log** (Admin → Access log): sign-ins, lockouts, accounts added or changed, links made, passwords set.
- **Headers:** strict Content-Security-Policy (no outside scripts), no framing, no referrer (keeps link tokens private), HSTS.
- **Files** are only served to the client that owns them and to the team, never cached.
- **Outbox** (`src/lib/outbox.ts`): every client email (GHL) and monday update is logged here and sent in order. If monday is down, the event shows "Didn't send" and the team can click **Send again**.
- **monday** (`src/lib/monday.ts`): column ids for the Hub Requests board (id 18440599608). Don't delete board columns without updating this file.

## Settings

| Name | Where | What |
|---|---|---|
| `MONDAY_API_TOKEN` | `.dev.vars` locally, Webflow Cloud secret in production | monday API token (secret, never in code) |
| `MONDAY_BOARD_ID` | `wrangler.json` | Hub Requests board |
| `HUB_URL` | `wrangler.json` (`.dev.vars` overrides locally) | used for "Open in Hub" links |
| `MONDAY_ITEM_PREFIX` | `.dev.vars` only | marks local test items, e.g. `TEST · ` |
| `SLACK_WEBHOOK_URL` | `.dev.vars` locally, Webflow Cloud secret in production | Slack Incoming Webhook for team alerts (secret; only `hooks.slack.com` is accepted) |

**Slack alerts** (`src/lib/slack.ts`): new requests, client replies and finished reviews post to one channel and @mention the owner (the Account Lead if nobody owns it; urgent new requests also the backup). Alerts carry the title and a link only, never the full message or files. Client text is escaped, so it can't trigger @channel or fake links. Set each person's Slack member ID in Admin → Team.

| Where | What |
|---|---|
| `src/app/(client)/` | Client screens: home, ask us, sent, requests, request, approvals |
| `src/app/team/` | Team screens: inbox, request, approvals, log a request, outbox |
| `src/app/actions.ts` | Everything that saves |
| `src/lib/sentences.ts` | The plain-language lines clients see (shared with the team's preview) |
